さて、では前回説明しなかった CONFIG.SYS によらない環境変数の設定方法だが…。なんてことない「.nyaos」(FATの場合は「nyaos.rc」)というファイルに記述しておけばいいのだ。これは拙作の NYAOS(S2NYAOS) が起動時に読み込むファイルで、記述内容としては、普通の バッチファイル と同じでよい。ここに「SET TERMCAP=F:/emx/etc/termcap.dat」などという行を記述しておけば、以後、NYAOS を起動する度にこのファイルを読んで、内容を再設定してくれるのである。つまり、NYAOS 上から起動するソフトに限っていえば、そのソフトの為の環境変数を変更する度に OS/2 を再起動するなどという愚かなことは全くする必要がないわけです、はい。

ボカッ

おぉ、無限ループである。こりゃいかん。というわけで、HOME に限っては例外扱いしなくちゃいかんわけです。どう例外扱いするかというと…、以下のどっちかの方法で定義してくださいまし。

  1. CONFIG.SYS に「SET HOME=《ホームディレクトリ名》」の行を追加する。
  2. NYAOS(S2NYAOS)のパラメータに「-h 《ホームディレクトリ名》」を追加する。

前者は OS/2 の再起動が必要であるのに対し、後者は NYAOS(S2NYAOS)の(アイコンの)プロパティーのパラメータ欄を変更すれば、次回のNYAOS の起動から、ただちに適用される。好きな方法を選んでくれ！

なお、以上の方法は、VIO系で特に NYAOS から起動するプログラムにのみ有効である。Workplace Shell からいきなりアイコンをたたいて起動つー、プログラムは out of 眼中なのだな。そういうプログラムをどぎゃんしたらいいのだろう。実は(VIOプログラムに限っては)逃げ道も無きにしもあらずなのだが、それはいずれ「.NYAOS の歩き方」を執筆してから説明しよう。

と、もったいつけてみる。

では、実際に .nyaos を書いてみよう。とりあえず、次のようなディレクトリ構成を前提にする。この通りでないといけないというわけではないので、適当にご自分のディレクトリ構造に置き換えて欲しい。

  • f:/usr … ホームディレクトリ
    • f:/usr/bin … ユーザの実行ファイルの置き場
    • f:/usr/dll … ユーザの DLL ファイルの置き場
  • f:/emx … emx のディレクトリ

これを設定する .nyaos は次の通りだ。

	ECHO ~/.nyaos reading...
	SET PATH=f:\usr\bin;f:\emx\bin;%PATH%
	SET TERMCAP=f:/emx/etc/termcap.dat
	SET TERM=ansi-color-2
	ECHO done

何かシンプルだなぁ。そんな一生懸命説明するほどのものぢゃないではないか。なお、LIBPATH は CONFIG.SYS , HOME は NYAOS のアイコンのプロパティーの方で設定するのを忘れないように。
