病院へ行こう 　(2003.10.16)

2

だが、おそらく、そんな懸念は無用だろう。なぜなら、翌週から一部のプログラムが本番稼働しだすのだから。それを想像するだけで…。

⊂⌒~⊃。Д。）⊃

仕
事で一日、シェルスクリプト書いたり、シェルスクリプト書いたり、シェルスクリプト書いたり。休みの日は自宅で、シェル書いたり、シェル書いたり、シェル書いたり。コマンドラインシェルについては、もう裏も表も知り尽くしていると言っても過言ではあるまい…。

そんなおいらに言わせると、sh って本当に芸術的だ。一見、仕様がものすごくシンプルに見えるけど、内部的には、結構富豪なことをやっていて、そのあたりに素晴らしいバランス感覚が感じられる。

例えば、普通に何も考えずに内蔵コマンドの仕組みを作ると、どうしても外部コマンドと差ができてしまう。が、sh は全く等価に扱えるのだ。


    cat hoge.log | while read line ; do
	echo $line
    done

まず、外部コマンドの出力を内部の「制御構文全体」に流し込めるなんて、もうガクブルですよ。内蔵コマンド、つまり、シェル内部でのサブルーチンコールにすぎないのに、fork までするなんて、貧乏性プログラマーにはとてもできない発想です。単純に、下手な工夫をせず、内蔵コマンドも外部コマンドと可能な限り同様の呼び出し方をしているだけ…とも、とれますけどね。

でも、下手な工夫をしないというところが大切なんですよ。これのおかげで、sh は単なるバッチ以上の自由度をスクリプトに与えている。まったく…これが UNIX 最初のシェルとは*1 …、破裂の人形*2みたいですわ、ほんと。

さらに while 文の条件にしても、続くコマンドのエラーコード == 0 の時に継続するというシンプルな仕様であるため、read の実行結果の「EOFか否か」を条件として利用できる。式評価などを test コマンド(角カッコね)に任せず、csh のように下手に数式評価機能などをwhile に組み込むと、こんなことはできない。

思うに、sh vs csh という構図は、UNIX vs Windows に似ている。とっつきの良さは csh / Windows の方が高いが、使う際の自由度の高さは sh / UNIX の方が高いのである。

ちなみに NYACUS はどうかというと…悪い意味でも csh に似ている。sh を目指して、できるだけ例外を排しようとしたが、CMD.EXE 使用モードの存在や軽量路線が足かせとなり、中途半端なままである、とほほ。tcsh ライクな操作性をうたっている NYACUS は結局のところ、本当に tcsh ライクなのである。

さて、一体、何が言いたかったんぢゃろ、わし。

内蔵 ls には内臓はないぞう 　(2003.09.28)

N
YA シリーズ 2.16 をリリースしました。OS/2系の方にとっては「今更」の感があるやもしれませんが、内蔵 ls を装備しました。

Windows系の方にとっては「何故 ls を」という話になりますが、そもそもは、NYADOS/NYACUS の前身 NYAOS-I では、バージョン 0.01 からカラーの ls を内蔵していたのです。理由としては、CMD.EXE を内部から呼び出すという仕組み上、最も利用頻度が高い DIR コマンドがワンテンポ遅くなるのが作者にとっては非常に気になったためです。

現シリーズで内蔵しなかったのは、ディスクが十分速くなった*9のでメリットが薄れたことと、DOS 上で動作する都合上、できるだけコード量を減らす必要があったからです。まぁ、それを何故今更実装する気になったかといいますと、NYACUS の(Cygwinに比べた)最大の強みが、１実行ファイルだけで手軽に UNIX ライクなコマンドラインを実現できる点にあり、それを伸ばすべきだと考えたからです。

つーか、私も客先の Windows サーバを操作する際、NYACUS だけ持っていって、ついつい「ls」と打って「あぎゃあ」と鳴いてしまったことがありまして…。この時は、即興で「alias ls "dir"」と書いた_nya を作りましたが、毎回作るのは面倒です。ならば _nya も一緒に持ち歩けばよいわけですが、持ち歩くファイルが一つ増えるのは、それでそれで、ちょっとメリット減です(ならば、ls.exe も持ち歩けばよいということになりますから)。第一、「DIR」の出力はダサい！

そう考えた末、不要かもしれない機能拡張を極力抑制する方針をちょっと緩めることにしました。その一つとしての内蔵 ls です。が、Windows系ユーザにとっては、シェルに ls が内蔵されていることは予想外のことで、いきなり ls = 内蔵の簡易ls では機能の違いにまどうことになるでしょう(MS Word のユーザのように!)。そこで、少々考えまして、

  1. コマンド名を ls ではなく list とした。
  2. NYAxS 自体に -a というオプションを設け、これを指定すると、ls , cp , mv 等を list , copy , move へのエイリアスになるようにした。

というようにしました。まぁ、オプション一つなら許されるでしょう。まぁ、将来的に GNU ls と比べてそれほど遜色ないものになれば、デフォルトで ls = list にするかもしれませんが…しかし、そこまでやるかな(多分、やらん気がする)。なお、カラーはまだ未実装ですし、表示フォーマットもオプションも貧弱です。あまり期待はしないでください。

他にも、ショートカットへの chdir (NYACUS限定)とか、コマンドライン上でのショートカット名→リンク先への置換(要option +lnkexp:これも NYACUS限定)とか、sh ライクな { }展開(これは全シェル対応)など、いろいろ意欲的に拡張しておりますので、勇気ある人は 2.16 をお試しください。

その際、Fn キー＋Ｅによる、CD-ROM の eject 機能がちょっと役立った。でも、Windowsキー＋Ｅによるエクスプローラーの起動とよく間違えるので、実は邪魔なだけである。

  • Fn キーはハードウェアメーカー用のショートカット用
  • Windows キーは Microsoft のショートカット用
  • ALT キーはアプリケーションのショートカット用
