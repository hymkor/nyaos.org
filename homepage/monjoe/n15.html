＿|￣|○ 鬱だ

話 は変わって…確かに「if( !strcmp(str1,str2) ){…} 」は気持ち悪すぎます。こういうコード書いてる人は…いや、なんでもありません。見かけ否定と肯定がひっくり返ってますからね。これでは一瞬「あれっ」となってしまいます。世の中、ゼロはゼロでもいろんなゼロがありますから、区別が必要ですよね。

NULL (void*型)
C言語における無効ポインタ。ただし、数値的にゼロだとは保証されていない。
0 (任意のポインタ型)
C++ における無効ポインタ。C++ では、キャスト無しで、void* 型を任意のポインタ変数に代入できなくなったため、NULL に変わり言語仕様として登場した。といっても、NULL 自体が 0 と定義してあるため、NULL を使っても問題ない(はず)。なんで、Java みたいに null っていう予約語にしなかったんだろう。
'\0' (char型)
正真正銘の1バイトの 0 を表わす。通常、文字列終結文字。
EXIT_SUCCESS (int型?)
エラー無しを意味する 0 。<stdlib.h> に定義されているが、マイナーなのか、誰も使っていない(私も)。せめて、<stddef.h>に定義しててくれればよいものを。<stddef.h> は他の std 系ヘッダファイルから、たいてい間接的に include されるので、ここに定義されていると使い易いのです。
false
C++ で定義された bool 型の「偽」を表す予約語。民間(?)では、よく「typedef enum{ FALSE , TRUE } bool_t; 」みたいに定義して代用してたりする。

これら全部知ってたら、プロ…というより、マニアです。軽蔑しましょう(あ、儂か)。まぁ、ここまでいかないまでも、一応、Ｃ言語分かりますというのであれば、せめて、'\0' と NULL の違いを理解してほしいところではあります。

あと、sizeof ですが、こちらの括弧は、私、使ってしまってます。とはいえ、たいていの場合は欲しいのは配列の物理サイズ(=byte数) ではなく、要素数なので #define numof(A) (sizeof(A)/sizeof(A[0]) ) というマクロを定義して、使うようにしていたりします。だから、sizeof 自体の使用頻度は高くないですね。

HimaScriptで書く　(2004.02.16)

常 々思うが、どんな OS においてもデフォルト状態で共通に使えるスクリプト言語が無いつーのは、他OS対応のソフトを作ってる身としては辛いなぁ。

  • Windows → WindowsScriptHost (JScript,VBScript)
  • OS/2 → REXX
  • DOS → なし (PC-DOS 7/2000 なら、REXX がある)
  • UNIX → sh,awk,perl

UNIX は NYAOS のプラットフォームではないので、JScript & REXX で書くようにすれば、問題ないんだろうけどね。

  • ECMAScript チュートリアル
    ふむ、HTML に組み込むのが前提のようですなぁ。

仕 事をしていて出逢う、一定の技術を持った人というのは、いろいろなポリシーを持っていて、おもしろい。以下、C言語限定だが。

コメントに日本語コードを使わない。
端末が常に日本語の読み書きできるとは限らないことからの配慮。昔の専用端末の中には、日本語が入っていると、動作がおかしくなることがあったようだ。
私的には、可読性が落ちるから反対だったんだけど、最近「他人のコメントはせっかく書いてもらっても、実は役に立たないことが多い」ということが判明(読み手を意識したコメントって、なかなか難しいようですなぁ)。微妙に自信が揺らいでいる。
goto の許可/禁止
個人的には、例外処理、多重loop脱出時には使ってもよい、つーか、むしろ使うべきだと思っているんだけど、やはり抵抗がある人が多いようだ。下手にフラグ変数を使うくらいなら、goto の方がマシだと思うんだけどな。
グローバル変数
本当にグローバルな用途に使うのは当然よいが、それ以外はダメといいたいところ。でも今回のプロジェクトでは、時間がなくて、パラメータが増加した時、経由関数のあまりの多さに、やむを得ずグローバル変数が使われた。後々、これが、必要悪として容認するかどうか、意見が分かれていた。雑談で、ですけどね。
return の後の括弧
括弧を付けた方が見易いと考えている人が古い人には多い。だが、下手に括弧をつけると、return のスペルを間違えた時、関数コールと間違われて、コンパイルエラーになるところがリンクエラーになってしまう。故に最近は括弧を付けない流れになってきている。が、実のところ、どうでもよい話だ。
マクロ
「strcmp(a,b) == RET_OK」(RET_OK は「0」を定義したマクロ) という記述を見た。個人的には、ちょっと気持ち悪いんだが、どこが気持ち悪いかというと、説明しにくいな。マクロが使用意図と外れたところで使われているからだろう。

思うに、素人向けに禁止とかタブーとか言われている機能は、頭から禁止と信じこむのではなく、理由を踏まえた上で、使いどころをわきまえるのが大切だろう。まぁ、とりあえずは

  1. まず、それを使わないことを学び
  2. 次に、それを「いつ」使うかを学ぶ

としていたら、間違いないだろう。goto しかり、グローバル変数しかり。いかん、説教くさくなってきた。

タスクをこなしてゆくとき、優先順位が高い奴を先にこなすのは当然なんですが、自己タスクの管理自体精神的にもしんどいし、タスクを切り変えること自体、エネルギーも手間をかかります。だから、もう一つのアプローチとして、優先順位として必ずしも高くないけど、すぐ終わってしまうものをチャッチャと終わらせてしまって、早いこと少数のタスクに専念できるようにするという方法もあります。これは上司からもらったアドバイスで、確かにある程度有効です。

まぁ、当然ながら予想できることですが、これは一つ間違えると、好きな仕事を先にやってしまうという誘惑の元でありまして…。かといって、7つも8つも、大きなものから、小さなものまでかかえているのは本当にキツいのであります。

さらに精神的に弱っていると、もう何をやっていいのやら混乱してきて、手を進めても、本当にそれが最優先にすべきことが確信も揺らいできて、集中力があがらず、たいして成果もあがってこなくなります。人格の kernel panic も時間の問題です。こういう日は、しんどいと正直に申告して、早めに帰りたいものです。

wildcats さん曰く「一つ一つの作業を丁寧にこなしていけば、その作業はどんどん慣れで作業自体が正確でかつ仕上げるまでの期間が早くなっていくと思いますしね 」

ある程度の定型的作業となるとそうですが、単発的な作業となると、「丁寧」にやり出したらキリがないという一面もあり、難しいところです。

自分は小心者だし、失敗したらエラいことになるので、本当に納得いくまで確認作業をしたい。ところが時間というリソースは限られているわけで、ある程度のところで「よし」としなくてはならない。それが、どの程度のところとするかは、その作業の質もあり、非常に難しいところ。特に本番環境作業の場合、この判断は実に辛い。
