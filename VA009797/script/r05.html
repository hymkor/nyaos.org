ルビーの首輪 (2000/12/03)

オブジェクト指向スクリプト言語 Rubyに見事にハマってしまいました。興味があったので、Ruby 本みながら、2,3 スクリプトを書いてみたら、ミイラとりぢゃないけど、ミイラになってしまいました(笑)。

  1. 私の作業領域である、どの OS(Linux,Solaris,OS/2,Windows,DOS)上でも動く。DOS でもスレッドできるそうですぜ、師匠！(←誰?)
  2. 国産らしく、日本語のコードあたりの処理は得意。
  3. OS/2 上での処理系は、多分、長沢さんのものだけなので、混乱がなくてよい。インストールも比較的しやすかった(ように思う)。
  4. perl のように -S オプションがあるので、extproc との相性もよろし。
  5. 誰か、win32ole(Win32 の COM にアクセスするモジュール)のOS/2 版(つーか SOM版)を作ってくれないかなぁ。(え、わたしっすか？ emx で SOM 触れるんなら考えますけど…ねぇ)
  6. 中括弧をほとんど使わないから、アンチＣ言語な人々にお薦めかもしれない。(個人的には中括弧好きなんだけど)
  7. ガーベッジコレクタがあるので、組んでると、Java っぽい感動がヒシヒシ(笑)
  8. イテレーターはいいねぇ。オブジェクト指向が生み出した文化の極みだよ。
  9. Ruby を CGI として使えるプロバイダは、いねぇがぁぁ？
  10. 作者の名前が平仮名表記しているのがいい。
  11. よく知らんが、SmallTalker にもウケそうな気がする。

ここまで並べりゃ、
「あ」の人も転ぶに違いない(誰?)

かなりどうでもいい項目も並びましたが(そうでもない？)、どうやら、この言語、当分、私のメインのスクリプト言語になりそうです。今まで、sh+awk , REXX , perl の間を、根無し草のように漂っていましたが、ひさびさに肌に合う言語に巡りあった感があります。そういう意味では Java も結構いい感じだったのですが、こちらはOS/2 で最新版が(誰でも)使えないとか、手軽さに欠けますからね。

しかし、ここまで気にいると、上にも書いたけど、「Ruby から SOM を操れたら格好いいなぁ」と、ひしひし感じまする。Windows 版 Ruby は COM を使って、Excel ファイルや Word ファイルをいじくることもできるのです。分散オブジェクト技術としては、COM の上をいっている(と噂で聞く)SOM でありますから、これを Ruby で操らずして、何を操ろうか！(いや、もちろん、他にもいろいろできますよ、はい)。やっぱり、「言い出しっぺの法則」が適用されるのだろうか。いや、それ以前に emx では SOM 関係が記述できんような話も聞きます。なんとか、ならんかなぁー。

しかしながら、SOM をサポートして何が楽しいかと言って、せいぜいデスクトップにアイコンを作るだけだったとしたら、それは「ルアーの馬車で、どぶねずみを運ぶ」だけのような気もしないでもない今日このごろ、いかがお過しですか？(日本語崩壊の序曲)

★≡≡≡≡

eff は、REXX の力を借りて、かなり、カスタマイズの幅が広がったはずである…のだが、よくよく考えると、このままではやがて「FD/2」(全て REXX で記述されているファイラー) になってしまうではないか。う〜む。一応、理想としているのは「FD-Clone」なんですけどね。

ちなみに eff は Vzのファイラーみたいにするつもりは無いんですが、今回の REXX の力を使えば、その辺のファイラーの真似はできるはずです。ダイアログ等が簡単に使えないのがネックかな。でも、やろうと思えばできるはずなので(FD/2 を見よ)、Vz と REXX が好きな人は挑戦してみてください(誰もいないと思うけど)。

REXX という言語は、正直、言語自体の魅力は皆無だけど、REXX.DLL を通じて、簡単にアプリから利用できるというのは、非常に魅力的である。API の使い方は rexxapi.inf というファイルに載っていたんだけど、どっからコレを入手したのかは忘れた(多分、BonusPakあたりだろう)。ただ、この API関数(RexxStartという)、引数が多い上に、やたら、キャストが必要で使いづらいことこの上ない。んなもんで、MyRexx というラッパークラスを作って使い勝手を良くして使っている。どんなクラスか知りたい人は、libeff/myrexx.h をご覧あれ。

REXX と同じように、アプリからマクロ言語として利用するのを前提にした言語として、GNU Project の「Guile」というのがある(OS/2 に移植されているかは不明)。こちらは Lisp インタープリタで、やがて Emacs の elisp は Guile になるとのこと。こいつが気軽に利用できるようであったら、eff を Lisp ファイラーにするという手もあるね。

REXX を利用することによって、eff は無限の拡張性を得たといっても過言ではないが(過言だ!)、その反面、OS/2 の世界からの脱出が益々困難になった。Guile という言語は、UNIX の世界からの賜物なので、こっちをマクロ言語にすることで、UNIX世界への進出も視野に入れたいもんだ。

まぁ、それ以前に、画面の入出力に関する、emx関数への依存がかなり高いので、それをまず何とかしなくては話にもならんのだが。一応、その手の部分は、ちょっとづつではるが、仮想化を進めているので、そのうち何とか、なるだろう。
