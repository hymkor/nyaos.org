ＡＳＰへ向かって撃て！ (2001/12/15)

敢
えて言おう、VisualBasicScript はカスだと！*1

いや、まぁ、そこまでいかないにしても、かなり、一苦労。そのカイあって、だいぶと慣れてはきたけれども...

  • 宣言文で、初期化できない
  • オブジェクトの代入だけは Set がいる。
  • オブジェクトの中にオブジェクトが入らない。
  • return 文。何それ？*2

つーのは、なんとかならんかな。とある協力会社の方も、VisualBasic では出来たことが、VisualBasicScript で出来なくてハマっておられた。

やはり、サーブレットと ASP は違いまっせ。サーブレットが本格的プログラミング言語 Java でコーディングできるのに対し、ASP は一介のスクリプト言語 VisualBasicScript を使うことになる。スクリプト言語は、即興で早くプログラムを書くのには適しているけれども、巨大なアプリケーションを組むのには向いてません、はい。

そんな、じゃじゃ馬 VBS を駆使して、懸案の i-mode用サーバサイドセッションを完成*3。スカラー型*4か配列しか放りこめない、ASP の Application オブジェクト*5に配列の形でクラスをセーブ・ロードするような仕組みで、強引に実現。ちゃんと、n 分経てば、セッション情報が削除されます。

そのかわり、全 ASP で 180行ばかりのコードを毎回 #include しなくてはならぬ。これで結構重くなってしまった。でも、VBS でこれだけのロジックを実現しようとするならばやむをえないよね*6。軽くするならば、VisualBasic を使って、COM で作るべきなんだろうが、そうして作った分散オブジェクトを ASP 上に置きつづけられるかというと、ちょっと疑問あるし。

しかし、リスト構造を自前で作ったのなんて、久しぶりだよ。最近、ずっと、可変長配列クラスを利用するのがあたり前になってきてたし。eff とか nyaos を作ってたころを思い出した。
