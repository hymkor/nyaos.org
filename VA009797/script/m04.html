J
-Phone の写メールで撮った写真(JPG)をPCに転送しようと、とりあえず、安直にプロバイダーにメール送信してみた。大方、普通の添付ファイルとして送られるのだろうと思っていたら、驚きました。メイラー(EdMax)が添付ファイルとして認識してくれません。本文にバイナリコードっぽい文字列がつらつらと。ヘッダはちゃんとついているようですが…

   Content-Type: image/jpeg;name="02-03-31_16-09.jpg"
おぉ、本文がイメージファイルだと、ヘッダで宣言しとるぞ。普通は

   Content-Type: text/plain; charset=iso-2022-jp
とか

   Content-Type: multipart/mixed; boundary="------------Boundary_=)c05GdKNDJi84n"
ですよねー。ということは単に画像だけ送るのではなく、本文にも何か書けばいいのかな。というわけで、本文もちゃんと書いたら、マルチパート形式になって、EdMax でも認識できるようになりました。やれやれ。

★≡≡≡≡

C
++ で、メンバ関数の継承がうまくいかないということがあった。


    class A {
    public:
	virtual A &operator << ( char c );
	A &operator << ( const char *s ){ while(*s) *this << *s++; }
    };
    class B : public A {
    public:
	A &operator << ( char c );
    };
    int main(){
	B hoge;
	hoge << "a";
    }

コンパイルすると、hoge << "a"; でエラーになる*1。B にoperator <<( const char *); という関数が無いというのだ。Digitalmars C++ でも、Borland C++ でも発生したので、コンパイラのバグではなさそうである。

どうやら、ある関数をオーバーライドすると、同じ名前の別関数もオーバーライドしないと、デフォルトでは継承されないらしい＝キャストとかスコープ演算子(::という奴)を明示的に使う必要がある。結局、下記の通り、オーバーライドされるものを別名にすることで解決した。


    class A {
    public:
	virtual A &write( char c );
	A &operator << ( char c ){ return write(c); }
	A &operator << ( const char *s ){ while(*s) write(*s++); }
    };
    class B : public A {
    public:
	A &write( char c );
    };

まぁ、同じ名前の関数で、一方はオーバーライドして、他はしないというのも不自然なので、こういう形にしてかえってスッキリした。が「引数パターンが違う」ことが「関数名が違う」ことと等価だと思っていたので、ちょっとハマってしまった。


*1 実際のソースはちょっと違いますので、これをそのままコンパイルすると、 別のエラーも出るかもしれません
