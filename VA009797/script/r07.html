The Call of NYADOS (にゃあどすの呼び声) (2001/01/24)

あり？V-Text 環境では駄目ざんすか？。ふみゅ〜、画面サイズを仮定するようなコードは書いてないはずなんですが…。とりあえず

us 
mode co80,50

と英語環境での V-Text 環境でのテストでは再現しないので、Win用の日本語 V-Text ドライバを入手が先決のようですねぇ。実のところ、BackSpaceコードとか CR とかダケで実現してあるので、動かないとしたら、それらがドライバとか環境側でサポートされていない可能性がありますねぇ。

ちなみに ls については、「alias ls dir /w」で逃げるという方法もありますです、はい。なお、わたくしは、かの SOS の開発者、新出尚之大先生のUNIX-like tools 4.12c の ls を使わせてもらってたりします。

しかしまぁ、細かいオプションを捨てれば、[TAB]x2 による補完リスト表示まで作ってるんだから、タイニーもんだったら、ls も作れんことも無いですね…(ちょっと迷ってる、今だ！(何が?))

一方、ＹＧ師からは、キーカスタマイズの要求が…。eff にも、設定ファイルに関するリクエストが…。俺の夢のようなぬるま湯生活は風前の灯(なんてね;-)。

それはそうと、リクエストに関しては「Warp なページのアンテナ」の電波圏内の人とか、「WebChain/2」で更新日時が見えている方に関しては、御自分のページで叫んでもらうだけでも十分わたしにまで届きますです。第三者に見えるという点では、こっちの方がいいかも。つーか、サポート掲示板 or ＭＬを作れよ ＞俺。って、需要あるのか！？ う〜ん、どうかな。

(25日朝 補足)

0.07 で、V-Text に対する不具合には対応しました。どうも、V-Text ドライバが ^H コードをうまく処理してくれないみたいですね。ということで、^H を使わず、ESC[D でもってカーソルをバックさせるようにしました。

そもそも何故 ^H を使っていたかというと、OS/2 の場合だと、^H で前の行の末尾にカーソルを移動させてくれるからなんです。が、DOS だと行を逆昇ることまではしてくれないので、実のところ意味なし。ということで躊躇なく、ESC[D にしました。まぁ、どーでもいい話ですが(笑)。

しかし、DOSでプログラム組むと、OS/2 の偉大さがヒシヒシと感じられまする。コマンドラインは 128 バイトまでだし、NYADOS の上から make しようとしても、すぐメモリが足りなくなるし…。NYADOS 自身もぼちぼち、スモールモデルの限界に近付きつつありますしね。これ以上大きくなると、far ポインタか…。う〜む。なんだかなー。うまく、クラスの中に far ポインタ隠せないかなー。つーか、できれば EMS か XMS も利用したいんだが。

あ、そんな制約の中、御希望のキーカスタマイズも実現させたんだから、感謝するよーに＞ＹＧ師。それにしても、奴め、キーバインドのどこを直したかったんだろう。そのうち、吐かせてやる。

★≡≡≡≡

長年の懸案事項であった、Windows9x 上でのコマンドラインシェル製作も何とか、目処が立ってきた。

今まで、結構手をこまねいていたのは、一行入力ルーチンを作成しても何故か日本語が入力できないという現象が発生していたからである。これは、どうやら「Windows9x の DOS窓では 32bit アプリケーションは日本語を一文字ずつ(rawmodeで)受け取ることができない」という仕様のためらしい。これへの対策も分かってきた…。

  1. NT か 2000 のコンソールでやる。こっちにはそんな制限はない(らしい)
  2. DOS窓に頼らず、kterm みたいな GUI 部分まで作ってしまう。
  3. telnetd を立ち上げて、teraterm で自分自身に telnet する。
  4. 16bit DOSアプリケーションとして作成する。

それぞれ、長所短所がありまして....

  1. 仕事は OS を選んでくれないんです。
  2. DOS窓を前提にしたソフトは動かない。また、GUI まで作る力(リキ)が無い。
  3. 上に同じ。
  4. 16bit アプリなので、メモリまわりがキツい。

で、結局、無難ではあるが、 4 で行くことにした。決め手となったのは

  • DOS の 16bit アプリケーションからでも、VFAT が参照できるのは、新出先生の UNIX ツールや、LFN対応KI-Shell で証明済み。
  • Turbo-C++ for DOS が free になった。

さて、作るにあたり、やはり楽をしたい。ということで、Turbo-C++ のクラスライブラリを使うことにした。本当は STL を使いたいところだけど、そもそも使えるかどうか怪しいし、使えたとしても、あのメモリ消費量で DOS に乗り込むわけには参らん。ということで、使い方をドキュメントで読んでみよう…

何じゃこりゃあ！

文字列クラスが「リファレンスカウンティング」をしていない！意味不明の方もいらっしゃる方がいらっしゃるやもしれないが、ある文字列変数の内容を別の文字列変数へコピーする際、何も考えずに全文字コピーしているのである。これは、いかん。効率を考えるならば、ポインタだけコピーして、文字列本体側の参照カウンターを増すような処理をすべきなのである。で、文字列に変更をする際に初めて、文字列の実体を複製するような仕組みをするわけだ。というわけで、いきなり、文字列クラスから構築し始めてしまった。何やってんだ、俺。

というわけで、ものすごく遠まわりをしてしまったワタシは工数の遅れを取り戻すべく、eff の一行入力ルーチンを拝借してくることにした。ベースライブラリが違うので、同一ソースにするのは 3 秒で断念し、とっとと、Turbo-C++ のクラスライブラリ向けに改造した。これは比較的順調。ただ、補完部分は、ディレクトリアクセス部分に互換性が無いので、とりあえず #if 0 で封印。

さぁ、道具は揃った(ような錯覚に陥った)。一行入力した結果を system 関数に渡すループを作って、走らせてみる。

おぉ、日本語バッチソだぜ

補完が無いので、まだまだヨワヨワだが、編集機能とヒストリが使える分、DOS窓をそのまま使うより、かなりマシである。

ワタシは調子に乗った！

勢いというのは怖いもので、残りの LFN 対応補完部分も、人のソースを参考にしつつ、エイヤっと実装してしまった。実のところ、かなり、おまじない風にやってるのが非常にコワいところである。ちゃんとしたAPI仕様書が欲しいな。

つーことで、何も無いよりはだいぶとマシなものになったので、調子の乗りついでに公開することにした。名付けて、「NYADOS(にゃあどす) -- Nihongo Yet Another DOS shell」である。まだまだ問題だらけ、という以前に、未完成のプログラムなので、公開はするけど、サポートはしない。そこんとこ、よろしく。
