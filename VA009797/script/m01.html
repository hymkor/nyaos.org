  • 改行は最終的に $T へ変換。

をやってみる。


alias which "
    foreach s .com .exe .bat 
	foreach d $pPATH.split$p
	    if exist %d%\$1%s% then
		echo found %d%\$1%s% at %d%
	    endif
	end 
    end
"

僅かながら、すっきりした。でも、環境変数をエイリアスの実行時に評価させるため、$p で % を表記しなくてはならないので、まだちょっと見にくい。うーん、関数装備かなぁ。やっぱり。でも、そこまでやるんだったら、素直に Ruby 使え、ゴルァ、だしなぁ。

ちょっと気付いたことだが、command.com(あるいは system関数か?)は\r(復帰コード)は行末と判断するようだが、\n(改行コード) は素直に制御文字として扱っていそうな雰囲気。CP/M*1の仕様だったのかな？

サイエンスはっくしょん (2002/01/14)

す
ることもないので、よせばいいのに、NYADOS のぱわぁあっぷ。結果、alias だけで、which コマンドが実現できるようになった。簡単に見えるが、これには、結構な改革の構造が必要だったのだよ。


alias which ^
    foreach s .com .exe .bat $T ^
	foreach d $PPATH.split$P $T ^
	    if exist $Pd$P\$1$Ps$P then $T ^
		echo found $Pd$P\$1$Ps$P at $Pd$P $T ^
	    endif $T ^
	end $T ^
    end

うぉぉぉ、わけわかんねー!!(爆)。ちなみに、$P は % に、$T は ; に置換される。また、行末の ^(キャレット)は、行の継続を意味する。

行の連結は、UNIX の作法では、バックスラッシュだが、DOS の場合は、「cd \」のように、ディレクトリ指定の \ が末尾に来る場合がある。そういう場合、都合が悪いので、検討の末、OS/2 の CMD.EXE の作法に従って、^ を使用することにした。そういう意味では、マルチステートメントを表す ; も、CMD.EXE に倣って、& にしなくてはいけないところだが…。まぁ、いいじゃないか。

しかし、ここまで来たら、いっそのこと、sh みたいな関数機能を用意した方が自然だな…。仕様検討中につき、公開は多分、来週か再来週だす。
