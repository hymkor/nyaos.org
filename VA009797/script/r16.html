sh は、よろしくないです。わたしはスクリプト記述言語に csh を使わないよう、部門内で sh の布教活動をしているくらいです。csh の欠点は、私が実感しているところでは下記の通りです。

％ シングルクォート内でも機能するメタ文字がある。
→ スクリプト内に他の言語(awk)などをインラインで埋め込むとき、とても不便。％ 標準出力と標準エラー出力を分離して操作しにくい。％ 内蔵コマンドを外部コマンドと同様に扱えない。

  1. については仕様の悪さを感じさせられます。
  1. は、やむを得ないと思うところですが、逆に sh では内蔵コマンドも外部コマンドとほとんど等価的に扱えるところに設計のスマートさが伺えます。それに比べると、csh は見劣りします。そういう点では、NYA*OS も内蔵コマンドはかなり例外的扱いなので、悪い意味でも csh に似ているといえるでしょう。なお、NYA*OS は、tcsh 風ではありますが、tcsh とは互換性のかけらもありません。

基本的に csh は、C言語に文法が似ていて、とっつき易いことだけがメリットだと思います。sh の文法体系の正しさは、その後継シェルが多くでていることからも示されているとってもいいでしょう(bash,ksh,zsh)。一方、csh の後継は tcsh だけです。

て、なんか、あたかも、あの文章の作者(翻訳者)の方みたいになってしまいましたが、まぁ、言いたいことはそういうことです。てなわけで、私は実は tcsh ではなく bash の方がスキなのです。

世の中、甘い、甘いぞ、ジョジョォォォォ

いや、確かに経験はそこそこ積んでいるが、勉強したのは前の晩だけである。後は、勘と受験テクニックだけで乗り越えてしまったという感じだ。なんか、Silver の時もこんなこと言ってたような。ええんかいな、Oracle。

実のところ、私は Oracle という DB を残念ながら評価していない。性能と信頼性はピカイチ*2だろうけど、その分、使い勝手とか、ユーザインターフェイスがないがしろになっているのではないだろうか。

  • Pro*C という、SQL組み込みのC言語では、プロトタイプ宣言ができない。VARCHAR2 に対応する変数を引数にするのが一苦労。また、C言語レベルでエラーが出たとき、行番号がずれるので、場所を探すのが一苦労。#line というプリプロセッサ命令を知らんのか。
  • SQL*Plus でコマンドライン編集ができない*3。シェル作者としては非常にはがゆいところではある。
  • Java でインストーラー作るなって。重すぎ。

扱いを難しくしているから、試験とか設けて勉強したユーザでないとちゃんと扱えないような代物になったような気がしないでもない。別に SQL Server を見習えとは言わないが、ちょっとは考えた方がいいかと。

あ、どうせ、薦めるなら、PostgreSQL か。MiracleLinux社も扱ってるしな。
