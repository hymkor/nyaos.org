未サポートのC++機能

特にバージョン記述が無いものは、emx 0.9d FIX 03 の話です。

auto_ptr(テンプレート)
<memory>に記述はあるが、#if 0 〜 #endif で無効にされている。
wstring(クラス)
<string>に記述はあるが、「//」で無効にされている。
_nls_is_dbcs_leadマクロ と -Zcrtdll オプション
-Zcrtdll オプションを使うと、リンクエラーが起きる。まだ、解消されていない。
STL と -Zcrtdll オプション(0.9d FIX 02 まで)
0.9d FIX 02 までは、-Zcrtdll オプションを使うと、STL が利用できなかった(リンクエラーが起きる)。FIX 03 にて解消された。
stringstream(クラス)
古い仕様である strstream しかない(「ing」が無いのに注意)。strstream は stringstream と違って、使用する文字列は char * をベースとしているので、若干不便なのである。

やってはいけないこと

そんなことするの、俺だけ？

string をメンバに持つクラスのコンストラクタで例外を出してはいけない。
実行時にセグメンテーションフォールトを起こしてしまう。
string のコンストラクタに 0 or NULL を渡してはいけない。
元々、const char * を使っているような箇所を string に置き換えるとよくあるので、注意。

コンストラクタが原因のセグメンテーションフォールトは、gdb でも発生箇所の特定がしにくいので、注意が必要です。

脚注

_nls_is_dbcs_lead
2バイト文字の先頭文字かどうかを判別するために用意されている、emx 標準マクロ。これを利用すると、DBCS 対応と唄える。ただし、上記のように emxlibc?.dll とまだ共存できない(バグだろ)。
-Zcrtdll オプション
標準Ｃライブラリをスタティックリンクせず、ダイナミックリンクライブラリ emxlibc?.dll を使用するよう指定するオプション。実行ファイルのサイズが小さくなるので、葉山は愛用している。
