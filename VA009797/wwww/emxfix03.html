超訳：emxfix03.doc (一部)

解説

emxfix03.zip は emx 0.9d の修正パッケージである。これは emxfix01.zip と emxfix02.zip と全ての修正と新規の修正を含んでいる

貴方がアプリケーションを作成するのに emx を用いているプログラマーなら、emxfix03.zip をインストールしなさい。単に emx を用いたアプリケーションを使うだけなら、emxfix03.zip に対応した emxrt.zip をインストールしなさい(ZIP のコメントを参照のこと)。両方をインストールする必要はない。

警告

emx 0.9d をインストールしていないのに、この修正パッケージを導入してはならない。これは emx の他のリリースでは動作しない。もっと後の修正パッケージをインストールしたのなら、emxfix03.zip をインストールしてはいけない。

本修正パッケージで解決される問題

[emxfix03.zip]

  • emxfix01.zip と emxfix02.zip は emxdoc 用にhtml.c と html.h を含んでいない。
  • fork() : 同一ハンドルで、addsockettolist() を二度呼び出さないようにした。
  • fork() : 256個のDLLをサポート(前は64だった)した。
  • 数値の引数をとる emx.dll のオプションが、16進数もサポート。
  • ソケットのクローズに関するバグの修正を試みた(Apacheで見られた)。うまく動作しないようなら、「set emxopt=-!0x800」を試す。
  • emx.exe が 1GB のメモリーをサポート(64MBだった)。
  • printf() : "%0f" の不正確な出力を修正。
  • printf() : "%.0f" の不正確な丸め(rounding)を修正。
  • printf() : "%#g" で、値 0.0 のための、数字の個数(number of digits)を修正。
    [訳注：桁数がおかしいってことか？！]
  • 'exception type_info node' (の名前)を解決するために、emxlibc*.dll より、もう一つのシンボルをエクスポート。
  • <ctype.h> でマクロ関数のために、プロトタイプ(宣言)を追加。
  • C++ の為に、ヘッダファイルで wchar_t を定義しないようにした。
  • as(アセンブラ): 入力行長さの制限を増加。
  • exp(): +INF(正の無限大)と-INF(負の無限大)のための不正確な結果を修正。
  • <limits.h>: LONG_LONG_MAX を LLONG_MAX等へ改名した。
  • <math.h>: cbrt() と cbrtl() は ISO C関数となった。
  • <arpa/nameser.h>: 入れ子のコメントを一掃した。

[emxfix02.zip]

  • emxfix01.zip は c_import.a の新バージョンを含んでいなかった。
  • strstr関数の実装がちょっとシンプルになった。
  • os2emx.h における全ての REXX の定義を #if … #endif で囲んだ。
  • emxdoc プロトタイプ(宣言)で (C++の[参照の]) & を[ポインタの] * と同様に扱っていなかった。

[emxfix01.zip]

  • scanf関数の "%[...]" は空でない一連の文字とマッチすべき[であるのに、マッチしていなかった？]。
  • malloc( ~(size_t)0 ) が成功していた。
  • fread関数で EOF を越えて、２バッファ以上のデータを読み込もうとすると、fseek関数が正しく動作しない。
  • テキストモードで read関数が "x\r\377y" を "x\ry" と読んでしまう。
  • <sys/un.h> TCPIPV4 マクロをテストしていない。[原文："sys/un.h> no longer tests the TCPIPV4 macro]
  • <ctype.h> と >stdio.h> でインライン関数のプロトタイプ宣言を加えた。
  • #pragma interface/implemetation は今度は正しく動作すべきだ[ひどい訳だ]。
  • libg++ (gpp.a) を上記修正の元で、再構築した。

本修正パッケージのインストール

  1. emxlibcm.dll や emxlibcs.dll を用いる全てのプロセスをストップする。OS/2 でプリロードされたプログラムを止めるには、
    emxload -qw
    を使う。
  2. emx をインストールしたドライブのルートディレクトリで、emxfix03.zip や emxrt.zip (解説参照)を、展開する。
    cd \
unzip -o emxfix03  (or `unzip -o emxrt')

    unzip のオプション -f , -u を使ってはいけない--- ヘッダファイルのタイムスタンプは更新されていない。

    DLL ファイルを作成できないことについての

    error:  cannot create emx/dll/emx.dll

    のようなエラメッセージが出たら、テンポラリなディレクトリを作成して、そのディレクトリ上でコマンドラインからemxfix03.zip のパス と emx の DLL ディレクトリのパスを(引数に)与えて、emxuzdll.cmd を実行する。

    mkdir \emxtmp
chdir \emxtmp
emxuzdll a:\emxfix03.zip c:\emx\dll
chdir ..
rmdir emxtmp

    これは DLL が使用中であっても、c:\emx\dll 内の DLL をemxfix03.zip 内の DLL で置き換えてくれる。新版の DLL は、DLL を参照している最後のプロセスが終了すると、間もなく有効になる。それゆえ、emxuzdll を走らせた後、リブートすべきである。さもなければ、新版が有効になったかどうか、いつ有効になったか分からない。(実際、DLL ファイルを含まないディレクトリが必要とするであろう一時ディレクトリを貴方は必要としない)

  3. 以下のコマンドを OMFスタイルのライブラリを再構築するためにタイプする(DOSの下では必要ではない)。
    cd \emx\lib
emxomf -s -l -q gpp.a mt/c.a st/c.a st/c_p.a
emxomf -s -l -q mt/c_import.a st/c_import.a

ライブラリの修正によるアドバンテージを得るには、貴方のプログラムを再リンクする。

どんな修正を導入したのかを知るために、ファイル \emx\doc\emxfix03.doc は保存すべきである。
