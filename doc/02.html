Ghost in the Commandline Shell

続 き！ 前回は、共通ライブラリ部分を取り上げた。Nihongo Nano Library は奥が浅い割に、まだ紹介していないクラスがあるのだが、全部解説していると、キリがないし、第一、読んでる方が飽きてくる可能性が高いため、一旦終わりとする。

今まではボトムアップで話を進めてきたので、今度はトップダウンで NYAxS の構造を説明したいと思う。ということで、テーマは「愛」…もとい「貝(シェル)」自体だ。

主に main の話

トップダウンに話をするとなると、避けて通れないのは main 関数である。NYAxS では、ずばり、nyados.cpp に存在する。NYAxS なのに nyados.cpp なのは、NYAxS 0.01 は NYADOS しか存在しなかったからだ。

main 関数をつらつらと見ていると、いろいろごちゃごちゃと、やれ

  • オプション処理
  • ヒストリ処理
  • _nya 読み取り処理

などが書いてあるが、そんなものを見るのは後回しでよい。実のところ、キモッ肝なのは(それはいいから) 次の２行である。


    InteractiveShell intShell;
    /* 数行おいてから */
　
    intShell.mainloop();

最初の行は変数宣言である。このオブジェクトは、対話型シェルを意味するクラスオブジェクトである。

そして、次の行の mainloop は、１行１行読みこんで、EOF まで逐次処理するというメソッド呼び出しである。が、このメソッド自体は InteractiveShell の親クラスNyadosShell で定義されている。

どうやら、本当のメインルーチンは .mainloop() のようだな！

シェル関係のクラス

またかと言われそうだが、ここでシェル周りのクラスの継承図を書いてみる。だいたいのクラス宣言は shell.h に記述されている。

NnObject
    ┗ NyadosShell (シェル)
	┣ ScriptShell (ファイル読みこみのシェル)
	┣ IntractiveShell (対話型シェル)
	┣ OneLineShell (引数の１行だけ実行するシェル)
	┗ BufferedShell (メモリバッファ上に蓄えられた文を実行するシェル)

要は、実行文の取り先ごとに派生クラスを用意しているということである。逆にシェルとして共通どころは全て NyadosShell に集約している。

OneLineShell , BufferedShell はちょっと何コレかもしれないが、要は if 構文とか foreach とかを実現する際に、IntractiveShell にしてもScriptShell にしても、読みこんだ文をすぐ実行せず、後から任意回実行ということがよくある。OneLineShell は１行こっきり。BufferedShell は n 行に対応したもんだ。

では、まずは、NyadosShell のクラス宣言(shell.h)を見てもらおうか。多分、重要どころは 2,3 のはず

NyadosShell のクラス宣言

注目すべきは、次のメソッドかな。

  • mainloop
    まさしく、これがメインルーチン。といっても、実は次の interpret と readcommand を交互に呼び出すだけ。
  • interpret
    セミコロン・改行で区切られた「１文」を実行するメソッド
  • readcommand
    セミコロン・改行で区切られた「１文」を読みこむメソッド
  • readline
    改行で区切られた「１行」を読みこむメソッド(仮想関数)。readcommand より呼び出される。

注意すべきは、readcommand は仮想関数では「ない」ということであろうか。シェルコマンドというのは、読みこみの単位は１行ずつであるが、実行の単位はセミコロン・改行で区切られた１文ずつなのである。readcommand は、各クラスの readline で１行を先読みして、それを文に区切って呼び出し元に最初のものから順に返すのである。行継続なども、readcommand が適当に相手をする(てきとうかよ！)

mainloop 関数周りについては、shell.cpp を参照くださいませ。

ここからは、readline の方向(コマンドを取得する方向)を上流、interpret の方向(コマンドを解釈する方向)を下流と呼ぶことにする。

ってことは１行入力ルーチンは「源流」か!?

まぁ、入力コマンドは上流から下流に流れるという意味合いですが、どっちにしても、サブルーチンが深くなってゆくんですけどね。では、どんどんシェルの奥地へ参りますぞ。といっても、いきなり下流の方に下るんだけど*1

一文とは！

ちょっと用語を整理する。

  • 一文 … 改行/セミコロンで区切られた１文(==１行とは限らない)
  • 個命令 … 一文を「|」で分割したもの

下流は次のように処理が流れてゆく。実のところ、これまでのところと違い、かなり“いびつ”になっているので、注意が必要だ。

  • interpret
    セミコロン・改行で区切られた１文を「|」(パイプ文字)で分割し、各々の個命令について
    • &追加処理
    • インタープリタ名挿入処理
    などを行ったのち、全文をまた連結して、次の interpret9 を呼び出す。何故また連結するかは後述する。
  • interpret9
    パイプに区切られた「先頭の」コマンドが内蔵コマンドか否かを判断して、処理を分岐させる。
    1. 内蔵コマンドの場合
      　内蔵コマンド用のプリプロセッサ関数(explode4internal)を呼び出してから、各コマンドを実行する。(NyadosCommand::run)
    2. 関数(subコマンドの方ね)の場合
      　関数の定義内容を BufferedShell オブジェクトに展開して、mainloopメソッドを実行する(再帰コール)
    3. 外部コマンドの場合
      　外部コマンド用のプリプロセッサ関数(explode4external)を呼び出してから、独自 system 関数(mySystem)を呼び出す

“いびつさ”には理由がある。NYAxS は、Ｃマガジンにも書いたように、COMMAND.COM / CMD.EXE を部分的に利用するためだ。その結果

  • COMMAND.COM / CMD.EXE との互換性を維持する。
  • パイプ処理など、難しい処理を回避し、初期バージョンを素早く立ち上げる

などの恩恵を得ることができた。で、COMMAND.COM / CMD.EXE との処理の切り分けだが、

  • パイプ処理以下は COMMAND.COM / CMD.EXE
  • それ以前のプリプロセス処理は NYAxS

となっている。しかしながら、これできっちりと分けられるかというとそうではなく、個命令単位でするプリプロセス処理などもあり、そのために、一度分割して、またくっつけるという処理をしていたりするのである。いやはや“いびつ”だ。

さらに！ NYAxS 後期バージョンになると、COMMAND.COM / CMD.EXE なしで動作する、Standalone モードが登場する。この Standalone モードの処理は、mysystem.cpp に記述されている。要は system関数と互換な関数を用意しているわけであるが…結局この中で、パイプ以下を分割して字句解析しなおしてということをもう一度やってしまっているのである。何て二度手間だ！

うぅ、だんだん、書くのが辛くなってきた

最初から COMMAND.COM / CMD.EXE なしで作ればよかったんですが…ね。でも、多分、それでは完成しなかったでしょうね。また、今から切り離すにしても、互換性の維持が困難ですから、無理っぽいです。とほほ。
