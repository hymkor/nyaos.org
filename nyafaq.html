素朴な

Cygwin で bash があるのに、何故 NYADOS/NYACUS を作ったんですか？
Windows95/98/Me では、WIN32アプリ上が何故か DOS窓での日本語入力を 読みこめないという問題があります。 Cygwin の bash も、この例外ではなく、日本語入力のできる Windows95/98/Me 用コマンドラインシェルが不在状態になっていました。

一方、世の中には LFN対応の KI-Shell というシェルが存在し、 DOS アプリケーションであれば、上問題がクリアできることが分かっていました。 が、KI-Shell の操作性は UNIX に慣れたユーザには辛いものがありました。 そこで、bash や tcsh ライクな日本語拡張コマンドラインシェルを 新たに DOS/Windows95/98/Me 向けに作成することにしたのです。
では、NYACUS は何故作ったのでしょう
当初の目的は NYADOS で果たせたわけですが、思った以上に、 WindowsNT/2000系でのニーズがありました。 個人的には当時どうでもよかったのですが 「貝が欲しいか…ならばくれてやろう」 と何かが降臨しますた。
なんで、0.28 の次が 2.00 なんですか？
NYADOS,NYAGOSの前身の OS/2 用シェル NYAOS (Nihongo Yet Another Os/2 Shell) とバージョンを合わせるために、2.xx からとしています。
NYAGOS（にゃあごす）はどこへ行きました？
諸般の事情で、NYACUS（にゃ～かす）と名前を改めました。 でも、やめときゃよかったかなと最近後悔してます。
NYAOS-I ってなに？
正式には Nihongo Yet Another Os/2 Shell 1.xx といいます。 作者が 1996年～1999年にかけてメンテナンスしていた、OS/2 向けのシェルです。 米国製の YAOS(Yet Another OS/2 Shell)というシェルを参考に 0 から作成しました。 現在メンテナンスは 1.65 リリースを最後に停止しています。 仕様的には、NYADOS/NYACUS/NYAOS-II の原型となっていますが、 未だに NYAOS-I しかない機能(「かんな」サポート、内蔵カラーls)も 存在しています。 NYADOS/NYACUS/NYAOS-II には NYAOS-I で学んだ教訓が随所に生きています。 生きてるんだってば。
NYADOS/NYACUS/NYAOS-II の総称によく「NYA*S」と書きますが、 そもそも、何て読むんですか？
「ニャースターシェル」とでも呼んでください（ぉぃ）
NYADOS/NYACUS について議論する場所はないのですか？
ないです（掲示板は廃止しました：過去ログはこちら） 今までそういうものは一切なかったのですが、 とりあえず、掲示板を用意しました。 必要であれば、メーリングリストの作成も検討しますが、 おそらく必要ないでしょう。 バグリポートなどは作者へのメールでも構いません。 それとも、SourceForge.jpでも使った方がいいでしょうかねぇ…。
パッチなどを送ると、取りこんでもらえるでしょうか？
おそらく取り込むことでしょう？ しかし、内容によっては拒絶する場合がありますので、ご了承ください。
自分で修正したバージョンを公開してもいいですか
GPL に沿う限り構いません。別に作者に連絡する義務もありません。
アンインストールするには
レジストリなどは一切触っていませんので、ファイルを全て削除して いただくだけで Ok です。

バグ?

aliasでコマンドを設定しても、再びNYADOSを使ったときに その設定が残っていません
仕様です。毎回、同じ alias を使いたいときは、 _nya というファイルに、その alias 文を書いてください。 (サンプルが ZIP ファイル内に入っていると思います) その_nyaを、nyados.exe と同じディレクトリか、 C:\ か、ホームディレクトリ(環境変数HOMEの差す ディレクトリ)のいずれかに置いておけば、 nyados が起動する度に_nyaの内容を(キーボードから タイプされたのと同様に)読み込みます。
二重引用符を用いたコマンドを & 起動しようするとすると、 コマンド名がタイトルだけになって、CMD.EXE だけが別窓で 起動してしまう(NT系)
「option start "start """""」 と定義してください。 NT系の start 句の仕様で、二重引用符が最初にあると、 タイトルと認識してしまいますので、これで回避します。
more を頻繁に利用していると、実行結果がプリンタに出てしまうことが あります。
NYADOS/NYACUSのせいではありません。 more での入力待ちの際に Ctrl-P を押していないでしょうか？ MS-DOS の機能として、Ctrl-P を押すと、出力をプリンターにも出すという ものがあります。それが働いているだけです。
バッチコマンドでの環境変数変更が、反映されません。
仕様です。高度な制御構文を利用していないバッチファイルであれば、 「source バッチファイル名」で実行できる場合があります。
source 文で読みこんだバッチの中でif errorlevelがうまく働きません。
DOS,Windows95,Windows98,WindowsMe など、command.com を利用する環境での OS の制限のためです。 standalone モードで、command.com を利用しないのも一つの手です。 具体的には「option +standalone」を _nya に入れると
  • if [not] errorlevel が正常に動く
  • メモリが 11KB 空く(command.com分)。
  • ほんのちょっとだけ高速になる(はず…)
というメリットがありますが、command.com の内蔵コマンド (dir , mkdir)などが利用できなくなります。これに関しては、 
alias dir "command /c dir $*"
alias mkdir "command /c dir $*"
と _nya に記述しておけば、回避できます。 なお、NYACUS では、standalone モードはパイプまわりがまだ不安定です。
設定ファイルがうまく読みこめません。
元々 _nyados , _nyacus , _nyagos といったファイル名でしたが、 管理がややこしいので、_nya に統一しました。 それらの旧ファイルが残っているということはありませんか？ _nyados , _nyagos も使用可能ですが、今後廃止する予定ですので、 なるべく使わないでください。 NYADOS , NYACUS で処理を変えるときは、%nyatype% で判別可能です。
カーソルが見えにくいです(WindowsNT,2000 上の NYACUS)
2.09 以降のバージョンをご利用ください。 スタートメニュー → 設定 → コントロールパネル → キーボードで、 表示の間隔などを調整いただくと、ちょっとマシになりますが… 根本的な対応を今検討中です。
NYACUS の STANDALONE モードで、パイプラインの右側に DOS コマンド (UNIX like tools の head 等) をつなげると
エラーです. 読み取り中 デバイス
中止 (A), 再試行 (R), 失敗 (F)?
と表示されることがあります。
これは…どうも、OS のバグか制限のようです。 NYAシリーズとは関係ない、某シェルでも同様の症状が確認されました。 そもそも、NYACUS を使う環境(WindowsNT,2000,XP のコマンドプロンプト) で、DOS コマンドを使うのが間違いとも考えられますので、Win32系の同様 のコマンドを利用して回避してください。

要望系

コマンドプロンプトヒアのようなことをしたい
アイコンにドロップしたり、送るメニューで送ったフォルダーを カレントディレクトリにして、起動したい。
スクリプトレベルで実現できます。 _nya に一行 「if not /%1/ == // cd --basedir %1」 「if not "%1" == "" cd --basedir "%1"」を追加し、 NYADOS,NYACUS のショートカットを送るメニューに入れてみてください。 送ったディレクトリをカレントディレクトリとして起動させることができます ディレクトリでなくとも、ディレクトリの下にあるファイルでも Ok です。 (例:.jar : 「suffix jar start」を_nya に追加する)
バッチ機能の強化は？
多分、これ以上はしないと思います。
  • WindowsScriptingHost
  • Perl
  • Ruby
  • REXX(OS/2)
などのスクリプト言語をお使いになることをお薦めします。
ls や mv , cp を内蔵して欲しい。
予定はありません。NYADOS の場合、メモリが限られているので、 必ずしもシェルに内蔵せずとも実現できる機能は内蔵しません。 UNIX Like なコマンド集としては、下記をお薦めします。
  • (DOS,Windows95,98,Me 向け) UNIX-like tools
  • (WindowsNT,2000,XP向け) NT版UNIX-like tools
(2003.10.04) 方針を転換し、ls については、list コマンドという形で 内蔵することにしました。また「nyacus -a」で起動すると、 ls , mv , cp がそれぞれ list , move , copy のエイリアスとして 定義されます。

ソース

ソースからビルドするコンパイラは何を使えばいいですか？
NYADOS はDigital Mars C++、 NYACUS は Borland C++ 、NYAOS-II は emx/gcc を利用ください。 いずれもフリーで利用することができます。 昔は Turbo-C++ もサポートしていましたが、今は外しています。
NYADOS/NYACUS/NYAOS2 は独自のクラスライブラリを使っているのは何故ですか？
STL 等のテンプレートは巨大すぎます。 NYADOS は DOS 環境での動作も想定しているため、実行ファイル自体を あまり大きくすることはできません。 ということで、最初は Turbo-C++ 付属のクラスライブラリ＋αから出発しました。 その後、
  • ライブラリ自体の仕様が気に要らなかった
  • 日本語サポート度が低い
  • 他のコンパイラでの利用も必要になった
等の理由で、少しずつ置き換えてゆき、最終的に独立したライブラリとなりました。 作者はこれを生意気にも Nihongo Nano Class Library と勝手に呼んでいます。
文字列ライブラリ NnString には二項演算子＋がないのは何故ですか？
二項演算子は、戻り値まわりの実行コストが大きい割に、 それほど、見やすいとは思えません。 かわりに、挿入演算子 << を用意しています。 「s = a + b ;」ではなく「s << a << b ;」を使ってください。 (完全に同じ動作というわけではありませんが)
ソースを見ると、コマンド実行部での shell.cpp と mysystem.cpp の役割分担が どうも不可解です。内蔵コマンドの実行などは mysystem.cpp から呼び出すべき では？
これは、NYA*S がコマンドの実行を COMMAND.COM / CMD.EXE に頼っているから です。STANDALONE モードの導入により、単独でのコマンド実行ができるように なりましたが、まだまだ非STANDALONEモードで利用することが多いため、 COMMAND.COM / CMD.EXE の代わりに実行する部分を一応分離しておいて、 off にできるようにしておく必要がありました。 これが mysystem.cpp に記述されているコードです。
